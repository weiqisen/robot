# 自主探索与视觉抓取高可用路线

> 状态：规划中，暂不实施。后续开发应先复核真机状态和本文件中的优先级。

## 当前判断

系统已经具备基础的失效安全能力：systemd 自动重启、导航安全闸门、雷达看门狗、传感器超时锁车、返航原点持久化、抓取参数方案和 Mac 日志采集。

当前主要短板不是“故障时能不能停住”，而是“故障后能否判断现场、自动恢复并安全继续”。单台 Jetson、单雷达、单相机和单电源也决定了它无法实现服务器集群式冗余；这里的高可用重点是故障隔离、降级运行、任务续跑和安全自愈。

## P0：优先实施

### 1. 独立任务监督器

新增 `mission-supervisor.service`，独立监控：

- `/scan`、`/map`、TF、Nav2 action 和相机/深度流更新时间。
- `explorer-agent`、`nav-safety`、`snack-butler` 的业务心跳。
- CPU、内存、GPU、推理延迟、进程重启次数。
- 底盘收到速度指令但地图位姿长期没有变化的异常。

恢复流程统一为：锁车、取消目标、停止机械臂任务、重启最小故障组件、重新校验依赖、恢复或终止任务。补充 systemd `WatchdogSec`、启动超时、重启频率限制和 `OnFailure`，识别“进程还活着但事件循环已经卡死”的情况。

### 2. 探索任务断点恢复

除返航原点外，持久化：

- `mission_id`、运行模式、任务开始时间和配置。
- 已访问区域、临时黑名单、最后目标和返航状态。
- 每隔约 0.5 m 记录的安全位姿（面包屑路线）。
- 地图版本以及 `map -> odom` 连续性签名。

进程重启后必须保持底盘锁定并进入 `RECOVERY`，重新检查地图、雷达、Nav2、安全闸门和机械臂。校验成功后按策略继续探索或沿安全位姿返航，禁止未经校验直接恢复运动。

### 3. 抓取动作恢复状态机

每次抓取建立唯一任务 ID，并在每个阶段原子落盘：目标确认、预抓取、下探、合爪、抬起、投放、回观察位。

如果服务在动作中重启：

- 禁止接受新的运动命令。
- 检查电压、关节数据和夹爪状态。
- 按“可能夹着物品”处理，优先安全抬升再回收臂位或观察位。
- 将原任务标记为中断，不能直接算成功，也不能自动重复抓取。

### 4. 视觉防撞独立化并失效安全

把深度保护盒检测拆成轻量 `visual-safety.service`，不依赖 YOLO、抓取状态机或 GPU 模型加载。

探索期间采用分级策略：

- 视觉新鲜：正常限速。
- 视觉短暂丢失：降为爬行速度。
- 视觉持续丢失：锁车等待恢复。
- 只有显式关闭视觉保护时才允许纯雷达模式。

### 5. 机械臂真实反馈

当前动作主要按预计时长推进，关节状态又可能只是驱动的开环回显。优先接入舵机真实位置、电流、温度或堵转状态；硬件暂不支持时，至少增加：

- 每阶段动作超时和连续无变化检测。
- 相机辅助确认机械臂是否实际移动。
- 下探、合爪阶段的独立严格超时。
- 异常时先抬升再回安全位，禁止继续投放。

## P1：第二阶段

### 自主探索

- 雷达、地图或安全闸门短暂中断时立即锁车，但进入“降级锁车 -> 自动恢复 -> 恢复任务”，多次失败后才要求人工接管。
- “没有 Frontier”必须经过连续 5–10 次地图更新、原地观察或小角度旋转、黑名单释放重评估后才能返航。
- 建立分级恢复阶梯：等待局部重规划、清理局部代价地图、切换候选目标、重启单个 Nav2 生命周期节点、重启导航栈。
- 返航优先走已记录的安全中间位姿，避免只向单个原点直接规划。
- 低压返航从固定阈值升级为结合返航距离、当前电压下降趋势的剩余能量预算。

### 视觉抓取

- 所有运动命令增加 `request_id`、过期时间和明确的 `accepted/running/succeeded/failed` 回执，防止重复点击或网络重发造成二次抓取。
- 合爪后验证是否夹到物品；抬升后确认目标已离开桌面；投放后确认夹爪释放。
- 连续空抓自动暂停该目标并等待人工确认，不反复执行相同动作。
- 记录 RGB、深度、内参和关节数据的帧龄；任一数据过期时拒绝使用旧坐标抓取。
- YOLO 故障采用熔断和降级：模型加载失败不反复占满资源，允许颜色识别或点击抓取继续使用。

## P2：基础设施与验证

- 对 YOLO、Nav2 和关键安全进程设置 systemd CPU/内存优先级与资源上限，避免 GPU/内存不足连带杀死导航。
- 使用版本化发布目录、原子软链接切换、部署后健康检查和失败自动回滚，避免直接覆盖线上脚本。
- Jetson 只保留限额 20–50 MB 的 SQLite WAL 环形缓冲；Mac/MySQL 不在线时暂存关键事件，恢复后补传。
- MySQL 设置数据保留与归档策略，状态按变化记录，避免固定频率全量状态无限增长。
- 增加指标：导航目标成功率、空抓率、任务恢复次数、平均恢复时间、传感器帧龄、推理延迟、服务重启次数和 GPU OOM 次数。
- 增加故障注入测试：杀死 agent、拔插雷达、断相机、Nav2 重启、YOLO OOM、MySQL 断开、网络断开和电池电压下降。
- 进行长时间真机测试：至少两小时连续探索，以及按物品类别统计的批量抓取测试。

## 推荐实施顺序

1. 独立监督器、systemd 看门狗、视觉失效安全。
2. 抓取动作日志与启动恢复状态机。
3. 探索任务完整检查点、面包屑返航和多周期 Frontier 确认。
4. 命令幂等、抓取结果闭环验证。
5. 机械臂真实反馈、资源隔离、原子部署与故障注入测试。

每一步都应遵循“先锁定运动，再恢复依赖，最后恢复任务”的原则。任何网页、网络或软件急停都不能替代物理急停和现场断电能力。
